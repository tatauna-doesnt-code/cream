# CREAM 1.8 UI review

Scope: the two supplied 1.7 screenshots, the current Qt implementation and rendered
1.8 flows. The goal is a usable first export without learning all advanced features.

## Findings from the supplied screens

1. Setup: the oversized title, files and optional filename editor remain visible on
   every page. Styling occupies nearly half of the skin-selection screen. Move each
   task into a focused page, retain a compact product header and add setup explanations.
2. Skin selection: checkboxes and highlighted rows have different meanings, but the
   actions do not explain the distinction. Make preview local to the list, label it
   “highlighted skin,” and show the number of checked rows on the export action.
3. Textures: the existing per-set accordions and overrides are useful. Keep them,
   enlarge the expansion target, remove table grid noise and explain preservation of
   unselected maps near the selection controls.
4. Export and recovery: four equally weighted actions hide the next step. Make export
   primary, retain a secondary configuration check, and elevate restoration only when
   a preview is active. Retain recovery access after a crash in Activity.
5. Optional tasks: updates/private access and naming deserve dedicated spaces. Keep
   automatic checks and show availability in the header, without permanent update bars.

## Implemented flow and verification

1. Setup — clear starting state, mapped import, source descriptions and collapsible
   project-layer requirements. Column mapping retains existing compatibility.
2. Skins — empty state, selection count, editable/resettable names, color swatches,
   preview action and navigation to textures. Original values survive preview/reload.
3. Textures — collapsed sets, partial selection, group resolution and individual
   overrides retained; summary updates from child or parent changes.
4. ZIP names — optional raw pattern, token insertion buttons, live filename and
   opt-in styled editor; fits at 900 × 700 in the SDK Qt test environment.
5. Export — primary counted action, explicit prerequisite guidance, live preview
   recovery banner. Controller tests exercise real DDS conversion and ZIP creation,
   cancellation, duplicate names, color differences and original restoration.
6. Activity and updates — log/recovery page and compact update dialog. Runtime tests
   verify safe reload, preserved state and rollback after an import failure.

Screenshots are generated by `scripts/check_workspace.py` in `dist/workspace-*.png`;
they use Qt/PySide from Painter with simulated project calls and a dark test palette.
They are not captures of a real open production project. No production skin was changed.

Accessibility improvements include descriptive field/control names, keyboard-native
Qt controls, textual selection/status feedback, color labels alongside swatches,
and focus treatment on the primary action. Full screen-reader behavior, OS scaling
and the exact host-theme contrast still require in-Painter testing; no accessibility
compliance claim is made from screenshots alone.
